# M² New Posted

**Your Voice. Your Space.** Социальная сеть на React / TypeScript / Vite и Cloudflare Workers / Hono / D1. Чёрно-белый интерфейс, русский язык по умолчанию. Это первая рабочая версия ядра, а не полная реализация всего master prompt.

## Состояние

Репозиторий начат с исходного README, существующий код не удалялся. Production не опубликован: Cloudflare CLI в текущей среде не авторизован. Облачные Workers, D1 и R2 не создавались, платные ресурсы не подключались. `database_id` в `wrangler.jsonc` — явно обозначенный локальный placeholder.

Работают:

- Регистрация, вход, выход, HTTP-only сессии, смена пароля, завершение других сессий, удаление аккаунта с проверкой пароля, смена username и профиля. Owner создаётся только доверенной CLI-процедурой по ID.
- Посты с изображениями, ответы, последовательные ответы как цепочка, редактирование, удаление, цитаты, лайки, репосты, закладки, хештеги, упоминания, права на ответы, закрепления, серверные черновики. У постов постоянные ссылки.
- Ленты «Для вас», «Подписки» и «Новое», cursor pagination по 20 постов, бесконечная прокрутка, pull-to-refresh на мобильном, скрытие просмотренного, блокировки и игнорирование. Логика ранжирования описана в [архитектуре](docs/ARCHITECTURE.md).
- Профили `/@username`, отдельные вкладки публикаций / ответов / медиа / репостов, поиск людей, постов и хештегов, недавние поиски, популярные темы.
- Уведомления с группировкой и счётчиком, отметка прочтения; личные диалоги с текстом и изображениями, пагинация, прочтение, удаление своих сообщений, жалобы. Обновление через обычные API, без платного realtime.
- M² Free / Premium / Premium+ / Elite: серверные лимиты, баннеры, статус, три монохромных оформления профиля, расширенная биография, несколько закреплений, история правок, аналитика за 7/30 дней. Только администратор или Owner может выдать, продлить или отозвать Premium, в том числе бессрочный. История и audit log; автоматическое применение срока при каждом запросе. Служебные значки выдаёт только Owner отдельно от Premium.
- `/admin` и `/admin/premium`: реальные счётчики, поиск пользователей, ограничения и снятие ограничений, роли, Premium, жалобы, модерация постов, журнал, обжалования. Owner управляет регистрацией, техобслуживанием, названием, правилами и объявлением. Проверка прав на каждом запросе.
- Тёмная, светлая и системная темы, адаптивная навигация, skeleton / empty / error states, диалоги с фокусом и Escape, reduced motion, экспорт собственных данных, PWA с безопасной offline-страницей.

**Честные ограничения:** закрытый профиль сейчас означает «посты видны только владельцу», запросов на доступ нет. Основные элементы интерфейса переводятся на английский и казахский; часть расширенных форм, системных сообщений и текстов пока на русском. Аналитика считает только уникальные события вошедших пользователей за сутки; текущая активность администрации измеряется непогасшими сессиями, а не online-присутствием. Список диалогов ограничен последними 50, уведомлений — 60, экспорт — до 10 000 своих постов/сообщений. Поиск по SQLite LIKE, а не полнотекстовый FTS. Все production-данные начинаются пустыми; демо-аккаунтов и seed-публикаций нет.

Ещё не реализованы: email verification, отдельный редактор многочастных цепочек, опросы, пользовательские списки, отдельные публичные комнаты обсуждений, отложенные посты, безопасные link previews, анимированные баннеры/рамки/персональные link pages, перетаскивание порядка закреплений и скрытие вкладок профиля, точная активность аудитории по часам, уведомление об истечении Premium, подгрузка всей истории уведомлений/диалогов, R2-адаптер, настройка логотипа/лимитов/feature flags через Owner UI. Ссылка «поделиться» копирует текст статуса Premium, это пока не графическая подарочная карточка. [План продолжения](docs/PROGRESS.md).

## Локальный запуск

Node.js **24 LTS**, npm. В первой вкладке терминала:

```sh
npm ci
npm run build
npm run db:local
npm run dev
```

Откройте **http://localhost:8787**. Wrangler запускает настоящий Worker с локальной D1. `npm run dev:ui` во второй вкладке даёт Vite HMR на http://localhost:5173; прокси обращается к Worker на 8787. Ключи не нужны. Для запретов записи в домашнюю папку задайте `XDG_CONFIG_HOME` и `npm_config_cache` в доступный рабочий каталог.

После изменений UI выполните `npm run build` для предпросмотра через Wrangler. Локальная база хранится в игнорируемой `.wrangler/`, не в `localStorage`. На устройстве сохраняются только тема, язык и настройки внешнего вида; cookie сессии недоступна JavaScript.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run test:e2e
```

`npm test` запускает unit-тесты безопасности и интеграционные API-тесты настоящего Worker + SQLite/D1 через Miniflare, не мок API. Playwright проверяет desktop-регистрацию, создание и лайк поста, серверные черновики, изменение профиля, сохранение темы, запрет админки обычному пользователю, мобильную навигацию, переполнение, offline fallback и отсутствие приватных данных в PWA-кеше. Для браузерных тестов нужны собранные assets и миграции; Playwright сам поднимает dev-сервер, если 8787 свободен. На Linux по умолчанию используется `/usr/bin/chromium`, для другого браузера укажите `CHROMIUM_PATH`; в CI используется установленный Playwright Chromium. QA-аккаунты появляются только в локальной тестовой базе.

## Cloudflare Free: подключение и деплой

Платная подписка не нужна. Не подключайте Workers Paid. R2 не используется: даже при наличии бесплатной квоты он может требовать платёжные данные. Перед созданием ресурсов проверьте актуальную доступность Free в своём аккаунте; при запросе платежа остановитесь, этот проект запускается локально без него.

1. Выполните `npx wrangler login` на своём компьютере и убедитесь через `npx wrangler whoami`, что выбран нужный бесплатный аккаунт.
2. Создайте базу: `npx wrangler d1 create m-new-posted`. Скопируйте возвращённый UUID в `wrangler.jsonc` → `d1_databases[0].database_id`. UUID не секрет, токен туда не добавляйте. Альтернатива: задайте `CLOUDFLARE_D1_DATABASE_ID` и выполните `node scripts/configure-d1.mjs`.
3. Примените **production**-миграцию: `npm run db:remote`. Локальная и production-базы отдельны; локальные тестовые пользователи не переносятся.
4. Выполните `npm run check`, затем `npm run deploy`. Wrangler покажет фактический URL вида `https://m-new-posted.<ВАШ-СУБДОМЕН>.workers.dev`. Наличие имени `m-new-posted` не гарантирует адрес без субдомена аккаунта.
5. Откройте URL, проверьте `/api/platform` и выполните регистрацию/публикацию. Только после этого считайте сайт опубликованным.

Точная последовательность для первого Owner, GitHub Secrets, обновления и восстановления — ниже и в [DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Хранилище

Бесплатный fallback хранит бинарные изображения base64 в D1: только PNG/JPEG/WebP, до **500 КБ** на файл и **5 МБ** на аккаунт, лимит 20 загрузок в час. Проверяются MIME и сигнатура, SVG/HTML запрещены. Получение файла проходит серверную проверку видимости поста / участия в диалоге / владельца. API и изображения отдают `private, no-store`. Это небольшое хранилище для первой версии, не замена R2 на больших объёмах. Суточный cron очищает неиспользуемые файлы старше суток и истёкшие сессии, reset-токены и rate-limit записи. Системный счётчик хранилища показывает исходные байты изображений, без накладных расходов base64 и SQLite.

## Первый Owner

Зарегистрируйте свой аккаунт на целевом сайте. На доверенном компьютере, авторизованном в Cloudflare:

```sh
npx wrangler d1 execute m-new-posted --remote --command "SELECT id, username FROM users ORDER BY created_at LIMIT 20"
npm run owner -- ВАШ_UUID --remote --confirm
```

Для локальной разработки замените `--remote` на `--local`. Скрипт проверяет формат UUID и назначает Owner **только если ни одного Owner ещё нет**. Проверьте возвращённую строку. Username не используется как доверенная сущность; первым зарегистрировавшимся права не выдаются. После назначения обновите страницу и откройте `/admin`. Далее только Owner назначает роли/других Owner. Для восстановления после потери доступа используйте доверенный доступ к D1 и зафиксируйте административное действие, не создавайте универсальный пароль.

## Автоматический деплой из main

В GitHub → Settings → Secrets and variables → Actions задайте:

- Secrets: `CLOUDFLARE_API_TOKEN` (Account → Workers Scripts: Edit, D1: Edit; ограничьте нужным аккаунтом), `CLOUDFLARE_ACCOUNT_ID`.
- Variables: `CLOUDFLARE_D1_DATABASE_ID`, `ENABLE_CLOUDFLARE_DEPLOY=true`.

Секреты не коммитьте. Workflow `Checks` проверяет main и PR. Workflow `Cloudflare Workers Free` на каждом push в main запускает проверки, браузерные тесты, миграции и деплой. Пока флаг не включён, он пропускается. Оба workflow используют npm lockfile. Создайте GitHub Environment `production`; дополнительные согласования включайте по своему процессу. Последовательные production-деплои не прерываются друг другом.

## Пароль и почта

Смена пароля работает без email-провайдера. Восстановление поддерживает Resend через необязательные Worker secrets `MAIL_API_KEY`, `MAIL_FROM` и `APP_ORIGIN`; до настройки API честно возвращает 503, токены в браузер не выдаются. Добавьте значения через `npx wrangler secret put ИМЯ`, затем redeploy; локально `.dev.vars` (пример в `.env.example`). Домен отправителя должен быть подтверждён у провайдера. Проект не создаёт почтовый аккаунт и не включает платный план. Email verification пока отсутствует.

## Обновление и восстановление

Для обновления: pull main → `npm ci` → `npm run check` → `npm run db:remote` → `npm run deploy`. Вносите новые миграции отдельными файлами, не редактируйте уже применённые. Перед изменением production-схемы создайте приватный экспорт: `npx wrangler d1 export m-new-posted --remote --output=backup.sql`; файл содержит личные данные и не должен попадать в Git.

При неудачном Worker-деплое: `npx wrangler deployments list`, затем `npx wrangler rollback <ПРЕДЫДУЩИЙ_VERSION_ID>`. Откат Worker **не откатывает D1**. Совместимые изменения схемы делайте аддитивно; ошибочные данные восстанавливайте через D1 Time Travel/backup после оценки влияния. Не импортируйте старый dump поверх работающей базы без отдельного плана. Подробности — [DEPLOYMENT.md](docs/DEPLOYMENT.md).
