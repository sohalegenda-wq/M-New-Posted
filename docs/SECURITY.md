# Модель безопасности

- Session token: 32 криптографически случайных байта; D1 хранит только SHA-256 токена. Cookie HttpOnly, SameSite=Lax, Secure на HTTPS, 30 суток. CSRF-токен отдельный, передаётся в X-CSRF-Token. Все мутации текущей сессии проверяют токен; Origin и Sec-Fetch-Site отклоняют cross-site. Только JSON/multipart. Тело запроса ограничивает потоковый Hono bodyLimit.
- PBKDF2-HMAC-SHA256, уникальная 256-битная соль, 100 000 итераций (WebCrypto в Workers). Пароль 10–128 символов. Это выбранный компромисс с лимитом Workers WebCrypto; перед широким запуском измерьте CPU на Free и рассмотрите специализированного auth-провайдера/усиление KDF в рамках платформы. Пароли, reset-токены и cookie не логируются.
- Восстановление: случайный токен на 30 минут, в БД только SHA-256, одноразовое атомарное поглощение через DELETE RETURNING. В ответе нет токена или подтверждения существования email. Без конфигурации почты — явное 503. Подтверждение email пока отсутствует.
- Длительность сессии проверяется при каждом запросе, роль и Premium читаются заново. Смена пароля завершает другие сессии. Заблокированный пользователь сохраняет доступ к сессиям/удалению/обжалованию, но не к записи контента.
- Права выдаются сервером: role_permissions, owner-only roles/system, administrator/owner premium, moderator+ moderation. Модератор не может ограничивать равную/старшую роль; пользователь — изменять чужой пост/диалог/черновик/файл. Premium не даёт административных прав. Bootstrap — доверенный CLI по UUID при отсутствии Owner.
- Мутации лайков, репостов, закладок и подписок идемпотентны за счёт compound PK. D1 batch связывает изменения Premium, ролей, модерации и audit. SQL значения всегда связаны через `.bind()`; SQL identifiers только статические. UUID зрителя в формуле рекомендаций очищен и получен из серверной identity.
- D1 rate limits: регистрация 5/час/IP, вход 15/15 мин/IP, reset 10/15 мин/IP, recovery 3/час/IP, посты 20/час/аккаунт, реакции 120/час, DM 60/час, новые диалоги 20/час, файлы 20/час, жалобы 10/час. Это базовый anti-abuse; распределённые атаки требуют дополнительного анализа. Запросы следования/профиля покрываются общей квотой Workers, отдельный лимит следует добавить при росте.
- React экранирует текст. Нет dangerouslySetInnerHTML и HTML-разметки постов. Упоминания/теги — React Links. Website допускает только http/https. CSP, nosniff, frame deny, referrer no-referrer. URL reset не попадает в сторонние Referrer.
- Uploads ограничены 500 КБ, image/png|jpeg|webp, MIME сверяется с сигнатурой. SVG/HTML и анимация не поддерживаются. Декодирования/перекодирования и проверки размеров в пикселях пока нет; это указанное ограничение, при росте необходим image pipeline. D1 квота аккаунта 5 МБ проверяется в атомарном запросе. Изображения и API не кешируются; ACL проверяется заново.
- PWA кеширует только общедоступные offline.html и icon.svg. API, сообщения, профили и медиа никогда не попадают в Cache Storage. Тема/язык хранятся локально, серверные сущности — D1. TanStack cache в памяти очищается при выходе через invalidation; не сохраняется между перезапусками.
- Ошибки SQL и тела запросов не публикуются. Production observability по умолчанию выключена; перед включением логов проверьте исключение личных данных. Не коммитьте .env, .dev.vars, backups, токены или локальную D1. API secrets только Worker Secrets / GitHub Secrets.

## Оставшиеся границы

Нет внешнего аудита безопасности, production-нагрузочных испытаний, email verification, MFA, защиты регистрации CAPTCHA или гарантированного антибота. Сроки хранения аналитики и audit пока не задаются через UI; удаление аккаунта удаляет связанные пользовательские записи с FK cascade, административный audit оставляет обезличенного actor NULL. Перед массовым запуском определите правила retention и условия платформы. Техническая первая версия не утверждает полного покрытия всех угроз.
