# Архитектура первой версии

Один origin: Worker принимает `/api/*` и `/media/*`, остальные запросы обслуживает Workers Static Assets с SPA fallback. React Router ведёт страницы, TanStack Query — серверный кеш в памяти, Motion — появление постов, Tailwind — утилиты; дизайн строится на общих CSS-токенах. Inter поставляется в сборке, включая кириллицу и расширенную кириллицу. Браузер не загружает сторонние скрипты или шрифты.

Hono-модули: core (identity, доступ, D1 helpers), auth, social, messages, admin. Все мутации принимают JSON или проверенный multipart для файлов. Zod строгими схемами исключает привилегированные поля из форм пользователя. Drizzle типизирует таблицы/запрос identity; остальная схема канонически описана SQL-миграцией, запросы параметризованы D1 `.bind()`. Административные мутации и запись audit выполняются одним D1 batch.

## Ленты

- Latest: `created_at DESC, id DESC`, только корневые посты.
- Following: та же хронология с EXISTS по подпискам.
- For You: посты последних 7 дней. Score = timestamp + min(likes, 50) × 60 000 + min(replies, 20) × 120 000 + 3 600 000 за подписку на автора + min(число знакомых хештегов, 3) × 900 000. Знакомыми считаются хештеги ранее понравившихся публикаций. Ограничение бонусов снижает влияние накруток; бесплатных внешних AI API нет. Это начальная эвристика, не обученная модель качества. Негативные сигналы: block, mute, hide seen, moderation hidden; приватные и заблокированные аккаунты исключаются до выдачи.
- Cursor передаёт `{score,id}` base64; LIMIT 21 определяет наличие следующей страницы из 20. Числа и UUID валидируются. Дубликаты дополнительно исключаются клиентом. В For You рейтинг может меняться при новых взаимодействиях; это не snapshot-consistent выдача. В Latest порядок устойчив для существующих постов. В профиле закреплённые посты выводятся первыми; отдельной перестановки закреплений пока нет.

Индексы покрывают автора/дату, parent/date, подписки и адресатов, лайки/post, хештеги, уведомления/user/date, сообщения/conversation/date, analytics/user/date. LIKE-поиск и ранжирование с коррелированными счётчиками рассчитаны на небольшую первую версию. При росте необходимы FTS5, денормализованные счётчики, материализованное окно рекомендаций и нагрузочный тест; готовой гарантии большого масштаба нет.

## Приватность и сообщения

Профиль может быть открыт или закрыт; закрытые посты доступны только владельцу. Реализовывать доступ «только одобренным подписчикам» следует через отдельные follow_requests, а не обход текущего фильтра. Block работает в обе стороны, убирает подписки, скрывает контент и запрещает новые сообщения. Настройка DM «от ваших подписок» означает: получатель подписан на отправителя. Текущие сообщения обновляются каждые 10 секунд только при открытом диалоге; список — 15 секунд, счётчики — 30. Скрыв вкладку, браузер останавливает интервальное обновление Query.

## Premium

Никаких платежей. Каждая выдача — отдельная запись premium_grants с actor, tier, expires_at, revoked_at. Новая выдача/продление завершает предыдущую и создаёт новую в одном batch с аудитом. Identity вычисляет действующий уровень при каждом запросе, а не доверяет клиентскому профилю. Пределы определены в `server/security.ts`, метаданные продублированы в миграции premium_features; при изменении добавляйте миграцию и тест согласованности. Истечение выключает возможности без фоновой задачи; уведомление об истечении — будущая функция. Уже созданный контент не удаляется.

## Аналитика

События `post_view`, `profile_view`, `follow`, `interaction`. Уникальный ключ viewer/type/target/day исключает дубли в течение суток. Собственные просмотры и анонимы исключаются. «Новые подписчики» — число полученных подписок за период, текущие подписчики — фактические follows; это разные метрики. За активность аудитории по часам/удержание интерфейс пока не выдаёт данных. Антибот-идентификации и внешнего трекера нет.

## Бесплатное хранилище

D1 uploads — временный небольшой backend хранения. Сохранение квоты проверяется атомарным INSERT SELECT; запрос медиа проверяет владельца или доступный пост/диалог/публичную карточку профиля. Все изображения имеют `no-store`, что защищает на общих устройствах, но увеличивает запросы D1. Суточный cron удаляет orphan uploads старше суток. Для большого продукта нужен R2 adapter после явного решения владельца о доступности бесплатного аккаунта, включая пересмотр квот, lifecycle и ACL. В текущем коде R2 не подключён.
